## 7. 評価の入口の仕様（A の実装。設計の承認の後）
```
python -m cases.r0_eval --config <名前 | JSON> [--rows R1,R2,... | all] [--quick] [--stress] --out docs/figures/r0_eval_<名前>.json
```
- `--config`：1 節の「構成の引数」。名前つきの既定：`basilisk`（既存の方式 (i)）、`conserving-base`（(ii)）、`r0`（確定した構成）。
- 行ごとの出力（JSON）：行の番号、配置の引数、測った値（格子・時刻ごと）、閾値、**合否（必の行）／記録（記の行）**、「悪化しない」の行は (i)・(ii) の値と、許容誤差 1e-11 での値、実行時間、許容誤差、コミット、GPU / CPU。
- R1・R4 用の場の保存先を引数で受ける。
- `--quick`：各行の最も粗い格子だけ（回帰試験用。`tests/test_r0_eval.py` が、導入前の値との一致を確かめる。合否は判定しない）。
- 導入前の値：`basilisk` と `conserving-base` で 1 回ずつ実行して JSON を残す（合否の判定には使わない）。
- 動かない行（資産の不足）は、JSON に「不足」と理由を書く。
