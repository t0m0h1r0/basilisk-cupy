# 88 二次元の再構築の階数不足：界面に寄せた窓（半径 5.5 セル）で、格子と平行な界面でも厳密な再現・連続性・4 次を回復（P1-1d）

**訂正（ノート90）**：このノートの「速度差の形」は、セル平均に拘束した最小二乗だった。直した形での測り直しは、ノート90 にある（精度は全体に良くなり、結論は変わらない）。

ユーザーの指摘：ノート87 の 7×7 の窓（49 セル、25 係数）は、総セル数は足りても、界面の法線方向の独立な情報が足りない。

- 格子と平行な界面（0°）では、法線だけに依存する区分 4 次多項式（9 係数）に対して、独立な法線方向の平均が 7 個しかない。そのため、界面のセルでも階数が不足する。
- 界面から 3.5〜4.5 セルのセルでは、界面の向こう側のデータがほとんどない。

設計の原則は、総セル数ではなく、法線方向と接線方向の情報量を確保すること。

```
python -m cases.galerkin2d_rank      # docs/figures/galerkin2d_rank2.json（旧構成の途中の結果は galerkin2d_rank_partial.log）
```

ライブラリは変えていない（`cases/galerkin2d.py` の `Reconstruction2D` の選択肢）。

## 定式化と理論的根拠
- **界面成分の階数**：最小二乗の行列を、通常の多項式 X（14 列、定数を除く）と、界面の折れの成分 Y（10 列）に分ける。`Z = (I − XX⁺)Y` の数値階数が 10 未満なら、相ごとの区分多項式は一意に決まらない。
  - 0° の 7×7 の窓では、法線方向の独立な平均が 7 個しかないので、法線だけの 9 係数に対して、少なくとも 2 方向の零空間がある（ユーザー）。
- **界面に寄せた窓**：窓の中心を、セルの中心から界面への足 `x_w = x_i − d_i n` に置く。候補のセルは中心からの距離 r < R で、重み `(1 − (r/R)²)²`（コンパクト支持、連続）に `(m_j/max m)^0.75` を掛ける。界面の両側に必ずデータがある。対象のセルの平均は最後のずらしで戻すので、窓の中心が対象のセルでなくてよい。
- **角度に依存した切り替え**：単一の多項式（5×5）の窓の法線方向の到達距離 `d_safe = (5/2)(|n_x| + |n_y|)` より遠いセルでだけ、単一の多項式を使う。`d_safe` から `d_safe + 1` セルで混ぜる。
- **速度差の形**：shift の写像を `P = u_i + Σ_{k≥1}(m_k − m̄_k)a_k`、`a = W(u − u_i1)` と書き直す（ユーザー）。厳密な計算では shift と同じで、一様な速度では a = 0 が丸め誤差によらず成り立つ。
- **界面がセル境界に重なる配置**：0° の界面がちょうどセル境界に重なると、切断されたセルがなくなり、法線方向の独立なデータが一段減る（測度 0 の配置）。半径 4.5 の窓では、そこで Z の小さな特異値が擬似逆行列の打ち切りを横切り、再構築が跳ぶ。半径 5.5 にすると、重なる配置でも満階数になる。
- **連続な SVD フィルタ**（ユーザーの 5.1 節）`f_τ(s)` は、跳びを連続にする。ただし、抑えた方向の情報を失う（重なる配置での厳密な再現が 3.5e-2）。窓で情報を確保する方が先（ユーザーの指摘どおり）。

## まとめ
| 問題 | 対策 | 結果 |
| --- | --- | --- |
| 0° で 7×7 が階数不足 | 界面に寄せた窓 | 全角度・全距離で満階数、厳密な再現 1e-14 |
| 界面がセル境界に重なる配置で階数が落ちて跳ぶ | 窓の半径 4.5 → 5.5 | 連続（密度比 1 でも 1000 でも） |
| 遠いセルで無理に区分多項式を解く | 角度に依存した切り替え | 単一の多項式の窓が一相に収まる所でだけ切り替え |
| 丸め誤差の自由流 | 速度差の形 | 自由流 1e-12〜1e-15 |
| 近接する界面の切り替え | **未対策**（帯が薄いと跳ぶ） | 孤立した界面の条件を明示 |

推奨の構成：`window="interface"`、`R=5.5`、`switch="angle"`、`diff=True`（`tau` は使わない）。
