# 39. 写像格子の CLS と GFM：界面の法線方向だけ細かくする

38 で、毛管波の減衰不足は δ/h（渦層の厚さ ÷ 格子幅）だけで決まり、演算子の次数では直らないと分かった。
そこで、界面の法線方向（y）だけ細かい写像格子で CLS と GFM を動くようにし、同じセル数で減衰がどれだけ良くなるかと、その費用を測った。

- スクリプト：`cases/capwave_normal_mode.py`（`mapping_y=`、`stokes=`、`plain=` を追加）、`cases/mapped_static_drop.py`、`cases/mapped_capwave_figures.py`
- 図：`docs/figures/mapped_cls.png`

## 定式化と理論的根拠
- **写像格子の微分**：計算空間 ξ の一様格子を `y = m(ξ)` で写すと、`∂_y = (1/m′(ξ)) ∂_ξ`（連鎖律）。CCD は ξ で微分して m′ で割る（ノート07）。CLS の輸送と GFM は、物理的なセル幅とセル中心の距離を使う。
- **毛管の刻みは物理的な最小セル幅で決まる理由**：格子規模の毛管波の振動数は `ω ~ √(σ/(ρΔ³))`（ノート66）で、最も細かいセル Δ_min で最大になる。計算空間の幅 h ではなく、物理的な最小幅を使う必要がある。
- **細かくして減衰が良くなる理由**：ノート41 の運動学の誤差は `M₂/δ²`、M₂ は面の間隔の 2 乗に比例する。界面の近くの間隔を α 倍細かくすると、M₂ は 1/α² になり、誤差も約 1/α² に下がる。本文の当時の解釈（δ/h の改善）と、ノート41 の解釈（M₂h² の縮小）は、同じ量の別の見方。

## 実装
| 部分 | 一様格子 | 写像格子 |
| --- | --- | --- |
| CLS の輸送 | 面の差分を h で割る | 物理的なセル幅で割る（`cell_widths`）。発散は `plain` のみ（`fccd` / `full` の補正は一様格子用の式なので拒否） |
| 質量・質量補正 | dV = h² | セル体積の配列（`grid.cell_volumes()`） |
| 曲率（ψ の CCD 微分） | | 変更なし（CCD は写像格子で連鎖律を使う、07） |
| GFM の鋭いジャンプ | j (H_R − H_L)/h | j (H_R − H_L)/（両側のセル中心の距離）（`centre_spacing`）。fd2 の面勾配と同じ距離 |
| 毛管の時間刻みの上限 | Δ = h | Δ = 物理的な最小セル幅（`min_width`。`grid.h` は ξ の幅なので使えない） |
| 再初期化、smooth 形、半陰的表面張力、表面粘性 | | 未対応（`NotImplementedError`） |
| 運動量の移流（BCG）、CFL | | 未対応（07 の 4f-3）。毛管波は線形なので `stokes=True` で比べた |
| 粘性 | Basilisk の `viscosity()` | 正方形の一様セルが必要なので `FD2Viscosity`（欠陥補正） |

- **恒等写像の確認：** 写像 m(s) = s（一様の間隔で写像の経路を通す）は、一様格子と同じ設定（plain、4 次の面値）で、振幅が 1.1e-8（相対）以内で一致した。差は解法の許容誤差による。
- **高速化：** `wall_distance` を毎回の境界値の設定で計算し直していた（モニタ写像の逆写像の評価）。これをキャッシュして、39 s → 14 s。

## 毛管波（法線モードから開始、1.5 周期、x 方向は 32 セル = 1 波長 16 点）
y 軸に `MonitorMapping(1 + (α − 1) exp(−((s − ½)/0.08)²))` を使い、界面 y = 0 の付近のセルを α 倍細かくした。

| 格子 | 粘性 | δ/h_min | 減衰誤差 | 周期の誤差 |
| --- | --- | --- | --- | --- |
| 一様 32² | ×1 | 0.92 | −20.6% | −4.9% |
| 32²、α = 2 | ×1 | 1.59 | −9.5% | −2.5% |
| 32²、α = 4 | ×1 | 2.56 | −4.5% | −1.9% |
| 32²、α = 8 | ×1 | 3.67 | −2.2% | −1.8% |
| 一様 64² | ×1 | 1.83 | −6.1% | −1.5% |
| 一様 128² | ×1 | 3.66 | −0.4% | −0.8% |
| 一様 32² | ×0.5 | 0.65 | −33.1% | −5.9% |
| 32²、α = 4 | ×0.5 | 1.81 | −7.3% | −1.9% |
| 32²、α = 8 | ×0.5 | 2.59 | −3.4% | −1.8% |

- **同じセル数で減衰誤差が小さくなる。** 32² のまま、−20.6% から −2.2% まで下がる。
- 同じ δ/h_min なら、ほぼ一様格子と同じ水準である。ただし、高い α では少し悪い（3.67 で −2.2%、一様 128² では −0.4%）。
  - 界面から離れた所のセルが粗くなる（α = 8 で h_y = 0.125）ためと考えられる（未確認）。
- 周期の誤差は x 方向の点数で決まり（30）、y を細かくしても −1.8% で止まる。
- **比較の条件：** この表の一様格子は、写像格子と同じ設定（plain、4 次の面値、Stokes）である。38 の既定の設定（`fccd` の補正、6 次の面値）では、一様 32² は −16.2% である。輸送の発散の補正だけで、減衰誤差が 4 ポイント変わる（38 には記録していない差）。

### 時間刻み
- 既定の毛管の上限は最小セル幅で決まり、刻みは (h_min/h)^1.5 倍に小さくなる（α = 4 で約 1/4.7）。
- 刻みを一様 32² と同じにしても（係数を合わせた）、1.5 周期で安定で、結果は同じだった。

| α | 最小セル幅の刻み | 一様 32² の刻み | その ½ |
| --- | --- | --- | --- |
| 2 | −9.47% | −9.52% | |
| 4 | −4.50% | −4.64% | −4.54% |
| 8 | −2.17% | −2.34% | −2.24% |

- この毛管波は界面が x 方向に沿うので、界面に沿った格子幅で刻みが決まると考えられる。
- ただし、格子規模の雑音に対する安定性は確かめていない。既定（最小セル幅）は保守的なままにした。

### 費用（CPU、1.5 周期、4〜5 本を並列）
| 格子 | 減衰誤差 | 時間 |
| --- | --- | --- |
| 一様 64² | −6.1% | 15.7 s |
| 一様 128² | −0.4% | 58.0 s |
| 32²、α = 2（一様の刻み、y の線緩和） | −9.5% | 37.6 s |
| 32²、α = 4 | −4.6% | 43.3 s |
| 32²、α = 8 | −2.3% | 51.1 s |

- **いまの実装では、CPU で同じ精度なら一様格子の方が速い。** 仮説（セル数が 1/16 なら速い）と異なる。
- 時間の大半は、写像格子のマルチグリッドの線緩和である（Thomas 法の Python ループ）。特に、`FD2Viscosity` の欠陥補正の前処理で多く呼ばれる。1 ステップあたりの呼び出しの固定費が支配的で、32² の配列の大きさは効かない。
  - 線を y 方向（写像の軸）だけにする `poisson.LINES_MAPPED_ONLY`：1.7 倍速く、結果は同じ。ただし、一様の軸を持つ既存の写像格子の振る舞いが変わるので、既定は False のまま。上の表の写像格子の時間はこれを使ったもの。
  - 試したが効かなかったもの：片方の色の線だけを解く（14.8 s → 14.8 s）。短い線を LAPACK でまとめて解く（15.2 s）。どちらも取り消した。

## 静止液滴（R = 0.25、μ = 0.1、等密度、液滴の上端 y = 0.25 の付近を α = 4 で細かく）
| 格子 | ε | max\|u\|：10 / 50 / 200 ステップ | ジャンプ（厳密 4） | 質量の変化 |
| --- | --- | --- | --- | --- |
| 一様 32² | 1.5h | 3.5e-4 / 1.1e-4 / 4.8e-6 | 4.0101 | 4e-15 |
| 一様 64² | 1.5h | 5.5e-5 / 3.0e-5 / 5.7e-6 | 4.0030 | 4e-15 |
| 32²、α = 4 | 1.5 h_min | 2.5e-2 / 2.6e-2 / 2.6e-2 | 4.1109 | 3e-15 |
| 32²、α = 4 | 1.5 h_max | 3.5e-4 / 6.9e-4 / 1.2e-3 | 4.0104 | 2e-15 |
| 48²、α = 4（h_max が一様 32² と同じ） | 1.5 h_max | 1.4e-4 / 2.5e-4 / 2.6e-4 | 4.0042 | 5e-15 |

- **ε は粗い所に合わせる。** ε = 1.5 h_min にすると、界面が粗いセルを通る所で ψ の幅が 1 セルに満たず、曲率が壊れる（寄生流 2.5e-2）。毛管波では界面が細かい帯の中にあるので、この問題は出なかった。
- 同じ N で一部を細かくすると、他が粗くなる（32²、α = 4 で h_max = 0.045、R/ε = 3.7）。そのため曲率が悪くなる（帯の平均 3.81、一様では 4.05）。
- h_max を一様 32² に合わせた 48² では、ジャンプは一様 32² より良い（4.0042）。寄生流は 2.6e-4 で頭打ちになり、一様格子のように減衰はしない。原因は未調査。

## 結論
- 写像格子で CLS と鋭い GFM が動くようになった。恒等写像では一様格子と一致し、質量は丸め誤差の精度で保たれる。
- **界面の法線方向だけを細かくすると、同じセル数で毛管波の減衰誤差が下がる**（32²：−20.6% → −2.2%）。38 の結論（δ/h で決まる）を、写像格子でも確かめた。
- **費用では、いまのところ一様格子に勝てない**（CPU）。線緩和の固定費が原因である。
- 静止液滴では、ε を粗い所に合わせる必要がある。寄生流が減衰しない点は残る。
- 既定値は変えていない（一様格子の振る舞いは不変。写像格子は以前は拒否していた）。

## 残り
- 線緩和の高速化（Python ループをなくす、GPU のサイクリック・リダクション、07 で予定していたもの）。これをしないと、費用で得にならない。
- 写像格子の静止液滴で、寄生流が減衰しない原因。
- 写像格子での `fccd` の発散の補正（38 の 4 ポイント差に関係する）。BCG 移流、再初期化。
- 界面が動く問題では、写像を界面に追従させる必要がある（移動格子）。今回は界面がほぼ動かない場合だけである。
